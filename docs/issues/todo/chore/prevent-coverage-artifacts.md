# Prevent Coverage Artifacts from Being Committed

**Status**: 🔴 Open  
**Priority**: Medium  
**Type**: Chore / Configuration  
**Assignee**: TBD  
**Created**: 2025-11-06  
**Labels**: `chore`, `git`, `ci`, `coverage`

## Summary

Prevent coverage artifacts (large JSON files, LCOV reports, etc.) from being accidentally committed to the repository. These files can be very large (100+ MB) and cause GitHub push failures.

## Problem Statement

During the `wami-condition` test coverage work, large coverage artifacts were accidentally committed:
- `crates/wami-condition/-` (138 MB) - accidentally committed coverage artifact
- `crates/wami-condition/coverage.json` (132 MB) - coverage report file

These files:
- Exceed GitHub's 100 MB file size limit
- Cause push failures with error: `GH001: Large files detected`
- Required `git filter-branch` to remove from history
- Can cause repository bloat and slow clones

## Root Cause

Coverage artifacts are generated by tools like:
- `cargo-tarpaulin` (generates `coverage.json`, `lcov.info`)
- `cargo-llvm-cov` (generates `coverage.json`)
- Other coverage tools

These files are not tracked in `.gitignore` and can be accidentally committed.

## Proposed Solution

1. **Update `.gitignore`** to exclude common coverage artifacts:
   ```
   # Coverage reports
   coverage.json
   lcov.info
   *.lcov
   tarpaulin-report.html
   htmlcov/
   .coverage
   .coverage.*
   coverage/
   **/coverage.json
   **/coverage/
   ```

2. **Add pre-commit hook** (optional) to check for large files:
   - Warn if files > 50 MB are staged
   - Block commits with files > 100 MB

3. **Document coverage workflow** in `docs/`:
   - How to generate coverage reports locally
   - Where coverage reports should be stored (CI artifacts, not repo)
   - How to view coverage without committing artifacts

4. **Update CI workflows** to ensure coverage artifacts are:
   - Generated in CI
   - Uploaded as CI artifacts (not committed)
   - Excluded from repository
